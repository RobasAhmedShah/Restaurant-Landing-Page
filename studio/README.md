# Calzone Point Studio

Standalone Sanity Studio, built into the website's `dist/admin` folder. It has its own React installation and is not embedded in the public React app.

## First-time activation

1. Authenticate locally: `npx sanity login`.
2. From this folder, deploy the schema: `npx sanity schemas deploy`.
3. Import the supplied menu: `npx sanity exec import-content.mjs --with-user-token`.
4. In Sanity Manage → project `vpdloifa` → API → CORS origins, add `https://calzonepoint.ca` and `https://www.calzonepoint.ca`. Allow credentials for Studio login on these exact origins. Add the exact deploy-preview origin when testing it. For local testing, add `http://localhost:3333` (Studio) and `http://localhost:5173` (website).
5. Invite the restaurant administrator from the project's Members settings.

The import uses generated menu document IDs and a legacy identifier to avoid duplicates. Re-running it preserves existing menu edits. The singleton settings document is published after the menu import succeeds.

## Editing

Open `https://calzonepoint.ca/admin/` and sign in with an invited Sanity account. Edit an item or website settings, then Publish. Published content is fetched by the public site when visitors load it, subject to Sanity CDN caching. No GitHub commit or Netlify rebuild is needed for content changes.

Use Visibility to hide an item, and Display Order to reorder it. Deals have an Included Items list shared between menu cards and the deal carousel. Photos and the restaurant logo use Sanity image uploads; video URLs point to an external video provider.

The public site uses the existing bundled content until settings are first published, or when Sanity cannot be reached. The search title and description update in the browser; existing static Open Graph and structured data are not automatically regenerated by CMS edits.

## Development

`npm run dev` starts the standalone Studio. `npm run typecheck` checks its schema/config types. At the repository root, `npm run build` builds the website and Studio together. Netlify uses Node 24.

Project ID and dataset name are public identifiers. Never put write tokens in `VITE_*`, commit them, or send them in chat.
